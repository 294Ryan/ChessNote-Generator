First of all, thank you for contributing to **ChessNote Generator**. You can help the project in the following ways:

- Submit bug reports with clear reproduction steps
- Suggest new optimizations or features (please submit an issue first)
- Improve documentation and guides
- Add or fix translations
- Contribute code, optimizations, or UI improvements for the desktop or Android app
- Write tests (the project has none yet)

The following sections cover the development workflow and the technical context you need to work on this project.

---

## **Setting Up**
Fork the repository on GitHub, then clone your fork:
```
git clone https://github.com/294Ryan/ChessNote-Generator.git
cd ChessNote-Generator
```

---

## **Installing Requirements**
Install only what the platform you work on needs:
| Name | Download or Installation |
| :-:| :--- |
| **Git** | https://git-scm.com/downloads |
| **Python 3.13+** (desktop) | https://www.python.org/downloads/ |
| **Python Modules** (desktop) | `pip install -r desktop/requirements.txt` |
| **PyInstaller** (desktop exe build only) | `pip install pyinstaller` |
| **JDK 17** (Android) | Bundled with Android Studio, or any JDK 17 distribution |
| **Android Studio** with Android SDK 34 (Android) | https://developer.android.com/studio |

---

## **Running and Building**

### Desktop
```
cd desktop
python main.py
```
Run it from the `desktop/` directory. Build the single-file executable with the committed spec:
```
cd desktop
pyinstaller ChessNoteGenerator.spec
```
The result is `desktop/dist/ChessNoteGenerator.exe`. The spec bundles `templates/`, the Noto Sans TC font, and the window icon.

### Android
Open the `android/` folder in Android Studio and run the `app` configuration on a device or emulator. From the command line:
```
cd android
./gradlew assembleDebug        # Windows: gradlew.bat assembleDebug
```
The APK is written to `android/app/build/outputs/apk/debug/`.

- `local.properties` (SDK path) is generated by Android Studio and is git-ignored.
- Release builds read signing info from `android/keystore.properties` with the keys `storeFile`, `storePassword`, `keyAlias`, and `keyPassword`. This file and any `.jks` / `.keystore` are git-ignored. **Never commit them.**

## **Desktop and Android Parity**
The Android app is a port, not a wrapper. Both apps must read and write the same files and produce the same output. When you change shared behavior, change both sides in the same PR, or state clearly in the PR which side is still pending.

| Desktop | Android |
| :-- | :-- |
| `core/models.py` | `core/Models.kt` |
| `core/project_io.py` | `core/projectfile.kt` |
| `core/pgn_renderer.py` (`resolvePgn`, `checkPgn`, board SVG) | `core/PgnService.kt`, `core/BoardSvg.kt`, `assets/pieces.json` |
| `templates/board.js` | `core/BoardJs.kt` (same code inside a Kotlin string) |
| `templates/opening_note.html.j2` | `core/ExportCss.kt` and `core/Exporter.kt` |
| `core/exporter_html.py`, `exporter_docx.py` | `core/Exporter.kt` (DOCX is hand-written OOXML, no Apache POI) |
| `core/exporter_pdf.py` (`QPrinter`) | WebView print in `MainActivity.kt` (system "Save as PDF") |
| `core/i18n.py` | `core/Texts.kt` and `core/I18n.kt` |
| `ui/theme.py` | `Theme.kt` |

Platform differences that are intentional: the desktop app always starts in English and remembers nothing between launches, while the Android app remembers language and theme, shows a welcome screen, and keeps an automatic backup.

## **Development Guidelines**

### File format
- A **draft** is JSON (`Opening.toDict()`); a **note** is the exported HTML with the same JSON embedded in a `<script>` marked `data-format="chessnote-project"`.
- Drafts and notes must stay interchangeable between desktop and Android. Adding a field means updating both ports and keeping older files loadable.
- `imageData` is the base64 PNG of an uploaded image. `imagePath` is a legacy desktop field that is preserved when saving but not used for display.
- Treat every opened file as **untrusted input**. `project_io.py` / `projectfile.kt` enforce limits on file size, text length, image size, pixel count, and node count, and regenerate missing or duplicate ids. New fields need validation too.

### HTML output safety
- Keep Jinja autoescape on (Android escapes the same fields by hand in `esc()`).
- Embedded JSON escapes `<` so data can never close the `<script>` block.
- The note must stay a single self-contained file: no external scripts, fonts, or images.

### Interactive board
- Only moves registered in the notes can be played; there is no engine.
- Edit `desktop/templates/board.js` first, then mirror the change in `android/.../core/BoardJs.kt`. The two must behave identically.

### Internationalization
- Never hard-code user-visible text. Desktop uses `t("key")` from `core/i18n.py`; Android uses `I18n.t("key")` / `S`.
- **Add a language**:
  - Desktop: one entry in `LANGUAGES` and one in `TEXTS` in `core/i18n.py`.
  - Android: add it to `Texts.languages` and `Texts.data`, and write a matching function in `Texts.kt`.
- A missing key falls back to English on both platforms.
- Language names in the menu are written in that language itself.

### Code style
- **Naming**: `camelCase` for variables, functions, and methods (Python included), `PascalCase` for classes, `UPPER_SNAKE_CASE` for constants.
- **Python**: no type hints, to match the existing code.
- **Comments**: English only. Add one only where the code is hard to understand without it. Single-line only, placed after the statement with 4 spaces before it:
  ```python
  font = app.font()    # Change the family only; keep the original size
  ```
- **Block headers** go on their own line above the block: `### Block Name ###` in Python, `// ### Block Name ###` in Kotlin and JavaScript, `/* ### Block Name ### */` in CSS.
- **Surgical changes**: change only what the task needs. Do not reformat, rename, or refactor unrelated code in the same PR. Report unrelated problems in an issue.
- Keep solutions simple. Do not add unrequested features, abstractions, or options.

### Testing
There is no automated test suite yet; tests for `core/models.py`, `core/project_io.py`, and PGN resolving are welcome. Until then, verify manually on every platform you touched:

- Open an existing `.json` draft and an exported `.html` note, edit, **Save changes**, and reopen.
- Type valid, invalid, and continuation PGN into a Line and check the board image and error message.
- Export `.html`, `.docx`, and `.pdf`; open each result. In the HTML, play moves, use Prev / Next / Reset, and click moves in the PGN.
- Switch language and theme; reorder items.
- For Android, also test rotation, leaving and reopening the app (backup restore), and PDF export through the print screen.

## **Submitting Changes**
- **Issues**: Search [existing issues][issues] first. For a bug, include the app version and platform, the exact steps, expected and actual behavior, and a screenshot or a minimal `.json` draft with private content removed.
- **Features**: Open an issue and discuss the idea before writing code.
- **Pull requests**:
  - Branch from `main`, one concern per PR.
  - Describe what changed and why. Add screenshots for UI changes.
  - State which platforms you tested.
  - Update the [README][readme] (including the FAQ) when user-facing behavior changes.
